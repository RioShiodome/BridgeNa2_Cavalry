# BridgeNa2_Cavalry 4.6.4 — 修复 AE 连接窗口第 28 行报错

4.3 修复 Cavalry 编辑窗口因桥接渲染而卡住、时间轴受干扰的问题：预览和烘焙都在独立的 Cavalry 进程执行。编辑端只导出场景快照，不调用 `api.render()`，不设置播放头。停止编辑约 0.45 秒后自动更新，无需切回 AE。

本次提供 **Mac 4.6.4**（arm64/x86_64）和 **Windows 10/11 x64 测试版 4.6.4**。Cavalry 仍自动安装一个 JS；AE 使用 Mac `.plugin` 或 Windows `.aex`。无需 Node、Python 或 CEP。Windows 随包附带系统 PowerShell 启动脚本和小型 Qt 启动 DLL，安装器自动部署。

4.4 改善：后台批次按耗时自适应；拖动 Cavalry 时间轴不再延后缓存发布；减少编辑端重复场景序列化和文件轮询；连接期间维持后台待命；AE 合并渐进更新，播放期间固定当前版本，停止后接收新缓存，避免逐段刷新反复打断 RAM 预览。

本机同场景 250 帧 / 50% 缓存、后台已启动时，4 次中位耗时从 1556 ms 降到 1187.5 ms（约减少 24%）；首段中位 84.5 → 82.5 ms，首段速度基本相同。数据只代表本次场景，不保证其他工程同幅提速。

**Windows 已完成代码、x64 构建、PowerShell/C# 检查和安装配置测试，尚未在 Windows AE/Cavalry 实机运行，因此按测试版交付。** Mac 已验证后台启动、异常退出和检查窗口重新连接；4.5 再次通过 250 帧缓存期间的 16 次时间轴操作和 2 次图层修改，并实测范围及透明 PNG 烘焙。授权状态仍取决于当前 Cavalry 账户；实际 AE RAM 播放流畅度尚未作完整量化。详见验证记录。

## 4.6.4 Connect / Choose composition 第 28 行报错

4.6.3 内嵌脚本第 28 行的路径正则 `/^[a-z]:[\\/]/` 在 Node 中合法，但本机 AE ExtendScript 会在解析时拒绝，导致选择窗口尚未打开就报语法错误。Windows 用户反馈点击 Connect / Choose composition 出现第 28 行错误；本次在真实 AE 26.2.1 / ExtendScript 4.5.6 中重现了对应脚本的解析失败，之前只用 Node 检查遗漏了这个差异。

4.6.4 先统一路径分隔符，再使用 ExtendScript 可解析的判断；合成选择和烘焙窗口从原生插件直接接收缓存目录，不再依赖 `$.getenv`。独立“创建动画图层.jsx”保护环境变量调用，必要时使用标准 AppData 目录；对重定向目录无法确认时明确提示从效果中连接，不猜测错误的缓存路径。

**Windows 用户请保存并关闭 AE 和 Cavalry，完整解压 4.6.4，运行 `Install-Windows.cmd`，重开两端后再次点击 Connect / Choose composition。必须更新 `.aex`，只替换 JSX 或 Cavalry JS 无法修复旧插件内部的脚本。**

真实 AE 脚本引擎已通过完整创建图层脚本的编译，以及选择/烘焙脚本的加载、中文原生路径、环境变量为空/缺失/抛错的检查。测试使用 Mac AE 和隔离的 Windows 路径模拟，没有操作用户图层；Windows 实际插件加载、渲染与播放仍未实测。

## 4.6.3 Windows 兼容性检查

- 统一 AE 选择窗口、烘焙窗口和创建图层脚本的缓存目录：Windows 使用 `USERPROFILE`，避免自定义 `HOME` 导致它们与原生插件读取不同目录。正常用户配置下对应 `C:\Users\用户名\Cavalry AE Native\default`。
- 修复后台快照和烘焙响应的路径比较：接受 Windows 盘符/路径大小写与正反斜杠差异，保留中文及空格；仍拒绝越界目录和错误通道。保留 4.6.2 按实际 comp 节点连接的修复。
- 安装器将 JS、启动工作区、插件和后台组件一起暂存、校验与备份，任一步失败会回滚，避免混用版本。CMD 固定使用系统 64 位 Windows PowerShell，包括从 32 位程序启动的情况。
- 后台进程兼容 Windows 10 的嵌套 Job，不再要求脱离父 Job；启动失败时记录退出码及 Qt 配置错误原因。此进程路径仍须 Windows 宿主实测。
- 新增 **`Check-Compatibility-Windows.cmd`**：完整解压后双击，检查系统架构、包内校验和、安装版本及缓存/后台状态；只读检查，不启动应用、不渲染。`Check-Renderer-Windows.cmd` 则用于打开后台登录检查窗口。

本次通过 JS/C++ 回归、PowerShell 解析、嵌入 C# 编译、Win64 结构布局检查、安装失败回滚与中文特殊字符路径测试。`.aex` 和 Qt DLL 均为 x64，导出入口正确，导入表只依赖 Windows 系统 DLL/UCRT，无额外 VC++ 运行库 DLL。PowerShell 测试在 Mac 的 PowerShell 7 中执行，**不等于 Windows PowerShell 5.1 或 AE/Cavalry 实机运行已通过**。目标系统仍须满足所用 AE/Cavalry 版本自己的要求。

## 4.6.2 选择 case5 却连接其他合成

现场工程的 11 个 comp 拥有同一个 `uuid` 属性，旧版把 UUID 当作唯一身份：选择窗口重新核对时取了第一个匹配项，编辑端和后台也会取第一个。这是 4.6.1 编号修复之外的另一个独立错误。

现在选择列表、绑定、编辑端、渲染快照和烘焙设置会话均携带实际 **comp 节点 ID + UUID**。绑定额外核对源工程路径；同名、复制出的相同 UUID 合成不会串线。后台结果记录实际 `sourceNodeId / sourceName`，可核对渲染对象。

**保存工程，正常重启 AE 和 Cavalry，然后在目标图层点击 Choose composition，重新选择 case5。** 旧绑定只记录了 UUID，无法可靠恢复原来的选择，遇到重复 UUID 会要求重选。旧版 JS 的合成列表会明确提示重启，避免混用版本。每个效果仍独立选择来源。

保存的工程按路径定位；另存为或移动源文件后需重新选择。未保存工程只在当前桥接会话有效，保存或重启后建议重新选择。插件不修改源 comp 的 UUID，也不改编辑端场景来生成身份。

实测：当前 11 个 comp 逐一解析正确；独立后台加载既有渲染快照，精确选中 `compNode#11 / case5`，以 25% 尺寸输出第 15、16 帧。没有关闭或保存用户编辑窗口。该测试证明节点传递和真实渲染路由；没有完成 AE 两层同时播放或 Windows 宿主实测。

## 4.6.1 选好合成后一直等待 / 不出画面

- **升级后保存工程，正常重启 AE 和 Cavalry，再在有问题的效果上点 Connect / Resync，选择合成一次。** 旧的缺失绑定会直接打开选择窗口，不再向不存在的来源反复发送。也可以使用 Choose composition。
- 选择前复查当前工程的 UUID；绑定文件写入后读回校验，AE 参数写入后也校验，失败明确提示。不会按同名合成猜测并自动改绑。

回归测试使用现场时间戳和单精度参数读写：原 4.6.0 稳定失败，4.6.1 通过，并覆盖编号边界、同毫秒冲突、缓存读回、磁盘写入失败、场景切换恢复与暂停。Mac 通用插件和 Windows x64 插件构建通过；本次尚未完成 AE/Cavalry 真实动画播放的端到端验证，Windows 也未实机验证。

## 4.6 多合成连接

每个 AE BridgeNa2 效果现在可独立选择 **当前 Cavalry 工程** 中的一个合成。支持多个 AE 图层分别显示不同动画；无需让 Cavalry 停留在正在显示的合成上。

1. 保存工程，正常重启 Cavalry 和 AE，加载 4.6.4。
2. 给 AE 图层添加 BridgeNa2_Cavalry，点击 **Cavalry composition → Choose composition...**；新效果第一次点击 Connect 也会打开选择窗口。
3. 在列表中选择合成并点“连接所选合成”。列表显示名称、尺寸、帧率、帧范围；同名合成按固定 UUID 区分。新建/删除/重命名后可点“刷新列表”。
4. 新建另一个图层（或复制原图层），再选择另一个合成。每层分别设置 Duration、清晰度、起止帧、透明背景和 Live sync。
5. Bake to current layer 使用该效果选定的合成，结果只回填目标图层。正在烘焙的效果需要先完成或取消，才能更换源合成。

效果标题标注选中的名称；内部按工程路径、节点 ID 与 UUID 绑定，重命名、调整合成顺序或切换 Cavalry 当前合成不会改绑。源合成被删除或换成不含该 UUID 的工程时，该路显示来源缺失并保留已完成缓存；打开原路径且包含原节点 ID / UUID 的工程会恢复，改连其他来源请重新选择。AE 工程保存通道编号，绑定和缓存保存在当前电脑用户目录；换电脑或清理缓存后需要重新选择合成。

各层有独立缓存、进度、暂停状态和烘焙请求。复制效果时自动分配独立通道并重新建立缓存。使用 **一个** 后台 Cavalry 按 FIFO 依次处理不同图层，等待时显示 Queued；多层可同时显示已有缓存，更新任务按队列执行。合成越多，总更新耗时越长。AE 正在播放时保留当前缓存版本，停止后接收更新。编辑端仍不创建/删除节点、不渲染、不移动播放头。

旧工程中未选择来源的效果可保留旧缓存；点击 Choose composition 迁移成独立连接。“创建动画图层.jsx”也会直接弹出合成选择窗口，不再写全局连接命令。

验证：双合成自动回归覆盖同名 UUID、不同尺寸/帧率/范围/清晰度/透明背景、单独暂停、编辑取消、缺失来源、缓存隔离和后台队列；选择与烘焙界面路由测试通过。独立 Mac Cavalry 实例已验证真实合成枚举、非当前合成指纹与编辑回调，图层/播放头/活动合成不变；该项测试使用渲染替身。尚未完整实测新版本在 AE 中同时播放两路真实渲染缓存，Windows 仍为无宿主实机验证的测试版。

## 4.5.2 撤销问题修复

旧版虽然把渲染移到了后台，准备预览和烘焙时仍在编辑工程里复制、删除临时合成和 Render Manager 项。这些脚本操作会干扰 Cavalry 的撤销栈。新版移除了编辑端的这些操作：只读取场景、导出快照、传递设置；创建渲染项、调整透明背景、枚举和修改烘焙参数全部在独立后台执行。不会用额外的“撤销同步”步骤挤占用户历史，也不通过自动保存工程实现同步。

烘焙窗口的设置保存在后台内存中，每次操作使用新的场景快照恢复设置；点击烘焙使用当时的动画内容。原来的范围、透明背景、全部可编辑 Render Manager 参数及 AE 原图层回填继续保留。复杂场景首次打开/应用烘焙设置可能要等待快照加载。

安装后请保存工程并正常重启 **Cavalry 和 AE**，确保两边及隐藏后台都加载同一版本。此前已经丢失的撤销记录无法由更新恢复；重启后产生的新编辑记录才能用于验证。自动检查覆盖编辑端零场景写入和缓存/烘焙流程；独立 Mac Cavalry 实测 59 个烘焙字段的读取与恢复通过。受本机辅助功能权限及测试实例登录限制，本次没有完成真实菜单 Undo/Redo 连续操作和整段实际渲染的端到端验证；Windows 仍未实机验证。

## 4.5.1 退出修复

修复隐藏的后台 Cavalry 在编辑器退出后残留、再次点击 Dock/Finder 时激活隐藏实例的问题。Mac 监督进程按编辑器实际偏好目录的运行锁定位编辑进程；编辑器退出或桥接下线时结束自己拥有的后台，AE 留着也不会继续拉起它。普通运行不再每 500 ms 无条件隐藏窗口；误激活后台时，在唯一编辑实例已明确定位的情况下返回编辑窗口。

Cavalry 不保证退出应用时触发 ui.onClose，因此生命周期同时使用进程身份和脚本状态；关闭回调先发离线通知，不再删除正在销毁的场景节点或操作界面。后台偏好文件已有时不再被每次启动覆盖。监督进程异常退出后，仅在会话、可执行文件和私有目录运行锁均匹配时接管其遗留子进程，避免多开后台。

本机已更新 4.5.1 文件并让新监控接管当前后台，未关闭编辑窗口。保存工程后正常重启 AE 和 Cavalry，可载入全部更新。如还在使用旧版而无法打开编辑器，可双击包内 **打开Cavalry-Mac.command**；它使用 macOS 的新实例启动命令，不强制退出进程、不保存工程。不要反复点击产生多个编辑窗口。

Mac 实测一轮渲染完成后的正常退出、后台清理和离线重启拦截通过，清理约 2.3 秒。第二轮编辑窗口能打开，但渲染验证被 Cavalry 重新登录提示阻挡，未计为完整通过；如遇登录提示，需在应用内完成登录。Windows 生命周期代码和构建检查通过，尚无 Windows 实机验证。

## 4.5 新增

- **Custom frame range**：启用自定义源帧范围；**Start frame / End frame (inclusive)** 设置起始、末尾帧。两端都包含，例如 20–29 为 10 帧。与 Cavalry 合成范围取交集，完全超出或起始大于末尾时停止同步并保留旧缓存。关闭后同步完整合成。Duration 仍决定这一段动画在 AE 占多少秒。
- **Transparent background**：预览副本的合成背景 Alpha 设为 0；关闭时沿用 Cavalry 合成背景。不会修改原工程或自动删除不透明背景图层。
- **Bake to current layer...**：烘焙窗口新增显式范围选择、起止帧与透明背景控件，首次打开沿用当前 AE 效果的选择。选择输出格式后点“烘焙到当前图层”，完成后回填原图层。透明输出建议 PNG；MP4 不支持 Alpha。正式烘焙仍使用 Render Manager 的独立质量设置。
- 大型场景减少反复单帧启动渲染；首批仍为 2 帧，后续以约 600 ms 为目标，在慢场景保留 1–4 帧最低连续批次（预测约 6 秒上限，单帧本身可超过它），最多 64 帧。代价是慢场景进度发布/响应取消可能要等当前批次完成，编辑窗口仍可操作。
- 编辑端按场景指纹计算成本调整检查频率；后台场景加载中不再每 2 秒重复打开同一快照。面板显示缓存帧/秒，`performance.json` 记录快照、加载、渲染耗时。

现场大型工程片段（65–80，共 16 帧，50%，完整帧率）同一后台进程交错比较两次：旧策略从加载至完成中位 29.38 秒，新策略 20.99 秒，减少约 **28.6%**；四次输出逐帧 RGBA 像素一致。这里只比较该片段，不代表整个 136 帧工程或所有工程都同幅提升；仍需实际计算每一帧。

## 4.4.1 后台启动修复

修复 4.3 在后台 Cavalry 已退出后仍报告 ready、导致任务无限显示“正在启动”的问题。Mac 用系统进程存活检查及退出自动释放的文件锁；每个任务必须收到自己的加载确认，不能用旧任务或 ready 状态代替。45 秒未收到回应、60 秒卡在加载时明确报错并保留旧动画；已确认正在渲染的长烘焙不受启动时限影响。

Cavalry 的 BridgeNa2 面板增加 **检查后台 / 登录**：打开私有后台窗口，完成可能出现的登录/授权提示后，在 AE 点击 **Connect / Resync**。Mac 也可双击包内 `检查后台-Mac.command`；Windows 使用 `Check-Renderer-Windows.cmd`。检查模式启动时跳过旧渲染任务，最多保留 10 分钟。Windows 从独立桌面切换到可见检查窗口时会重启自有后台进程，需重新连接。

## 安装和使用

1. 完整解压，Mac 双击 `Install-Mac.command`；Windows 双击 `Install-Windows.cmd`。安装器备份旧版，安装插件，并配置 Cavalry JS 随工作区启动。
2. 若 Cavalry 正在运行，按安装器提示自行保存并关闭后继续。安装器不会替你保存工程或强制关闭应用。安装完成后正常重启 AE，打开 Cavalry 动画。
3. 在 AE 运行包内 `创建动画图层.jsx`，设置秒数即可连接。已有图层也可以点 **效果 → Cavalry → BridgeNa2_Cavalry → Connect / Resync**。需要加快大工程时，先启用 Custom frame range 只缓存要用的片段。
4. 首次连接会启动后台 Cavalry，稍等其准备好。之后在 Cavalry 编辑，停下后自动重建动画缓存；AE 可以先播放已经完成的部分。

更新后保存并正常重启 AE 和 Cavalry，再点 Connect。不要同时启用旧版发送器。已有 4.0–4.3 AE 工程可以沿用效果。安装器不会删除工程、动画缓存或烘焙结果。

目标为 macOS 12+ 或 Windows 10/11 x64、AE 2024–2026，同时须满足 Cavalry 和 AE 的系统要求。实测为 Apple 芯片 Mac、macOS 15.6.1、AE 26.2.1x2、Cavalry 2.7.2。Intel Mac、其他 AE/Cavalry 版本未作宿主验证。

| Live sync | 接收新缓存；关闭后冻结现有版本 |
| Duration (seconds) | 完整动画在 AE 占用的秒数，控制图层出点 |
| Cache resolution | 25% 最快、50% 默认、100% 原尺寸 |
| Custom frame range / Start frame / End frame | 限定源动画区间（含首尾） |
| Transparent background | 仅把预览副本的合成背景设为透明 |
| Cached (%) | 已缓存帧比例和同步状态 |
| Bake to current layer... | 打开 Render Manager 参数与烘焙面板 |

编辑端把场景导出为不可变快照，后台加载快照后先输出 2 帧，随后根据实际耗时调整批次（1–64 帧，目标约 600 ms，复杂场景保留连续批次）。后台独占自己的渲染时间轴；编辑窗口的播放头不受桥接代码控制。编辑期间的真实内容修改会取消旧预览任务，稳定后提交新快照。

完成的缓存段先发布；未完成部分继续使用上一版完整动画，第一次缓存缺失部分透明。只有确认文件输出完整后才发布；AE 正在引用的已发布 PNG 不被重写。后台重启可从已完成前缀继续。启动失败会显示错误并保留旧动画，不切回前台渲染。

4.6 起，每个 BridgeNa2 效果拥有独立通道；连接、暂停和预览分辨率仅影响本效果。旧版默认通道仅用于兼容既有缓存。用 Duration 管理实时层时长，避免同时用图层拉伸或时间重映射改变它。

AE 同尺寸帧使用直接像素转换，缩放帧预计算采样位置；支持 8/16/32 位 AE 项目，但预览源为 8 位 PNG。插件保留最多 256 MiB 解码缓存。

## 烘焙到当前图层

1. 点击 **Bake to current layer...**。
2. 选择烘焙范围和透明背景，再选择格式与参数。参数分为 Render Manager 和合成 / 运动模糊；选中参数、修改，再点 **应用当前参数**。目录可选择，元数据可增删行。
3. 点 **烘焙到当前图层**。后台进程渲染点击时的场景快照；编辑端可以继续操作，之后的修改不会混入该次成片。
4. 完成后导入成片，以与原画布等大的预合成回填原图层，关闭 BridgeNa2_Cavalry 效果。变换、蒙版和后续效果保留，动画适配该层时长。

参数从当前 Cavalry 的真实属性定义读取，包括输出名称/目录、范围、分辨率、质量、CPU/GPU、格式/编码参数、动态渲染、目标重定时、渲染脚本、上传开关、元数据、帧率、背景透明度与运动模糊。格式切换后重新读取定义。只读状态、内部连接和目标合成绑定不作为可编辑数值。目标绑定当前连接合成，不在此面板添加其他合成。

本机检测到 PNG、JPEG、WebP、SVG、MP4、QuickTime、ProRes、GIF、WebM、APNG、Audio Only、Sprite Sheet、Lottie；实际可用性取决于版本和授权。列出选项不代表全部编码器、脚本和上传组合已实测。后台使用独立应用数据；依赖额外登录或自定义插件的输出可能需要另行配置，失败会保留原预览。AE 不能导入的格式会保留输出文件并提示；Sprite Sheet 是静态拼图。动态渲染有多个输出时可选择一个回填。

每次在输出目录创建独立 `Bake-...` 子目录，避免覆盖旧结果。图像序列进度按输出文件数显示；动态范围/重定时时总数仅作参考，后台明确完成且存在输出后才回填。视频编码显示耗时，不伪造百分比。

**取消回填**保留原预览并发送取消请求；后台同步 `api.render()` 已开始的批次可能要结束后才能响应，期间不占用编辑窗口。未完成结果不回填。烘焙支持 AE 撤销；继续实时编辑可撤销烘焙或创建新的实时层。烘焙后停用的插件不再改图层出点。

PNG 16 位、QuickTime 等正式输出由 Cavalry Render Manager 生成，经 AE 素材导入处理，不受 8 位预览限制。透明输出需背景 Alpha 为 0 且格式支持透明。若面板报告权限错误，在 AE 首选项允许脚本写入文件。

## 实际限制与文件位置

- 后台占用另一份 Cavalry 的 CPU/GPU 和内存，首次启动有额外延迟；资源竞争仍可能影响整机速度。大型场景的复制、指纹检查和快照导出仍在编辑进程中，可能短暂耗时。本次修复移除了耗时逐帧渲染对编辑端的直接阻塞，不代表任意场景零延迟。
- 4.4.1 实际测试使用已安装的 JS 和启动器：250 帧缓存、16 次时间轴操作、2 次图层修改通过。50 ms 编辑端采样最大间隔 57 ms；该测试场景不能代表任意大型工程。单元回归同时覆盖编辑端禁止调用渲染/设帧。
- 后台仅在私有偏好目录验证通过后打开快照。Windows 使用 Qt 的启动扩展入口启用独立 `qttest` 数据目录，并在单独桌面运行渲染窗口；不会修改 Cavalry 安装目录、注入运行中的进程或修改系统文件夹配置。不会打开或保存用户编辑窗口的工程。连接启用时维持待命；断开连接且无烘焙需求约 90 秒后退出；编辑器退出/桥接下线时优先关闭它，拥有它的 AE 实例退出时也会关闭它。
- 隔离渲染实例依赖 Cavalry 的有效登录/授权；遇到登录窗口、许可证不足或版本不支持时不会绕过授权，可能无法启动渲染。若出现后台未就绪，点击 Cavalry 桥接面板的“检查后台 / 登录”，处理提示后重新连接；详细错误保存在 `renderer-health.json` / `last-error.txt`；此限制尤其需要在 Windows 首次使用时确认。
- 工程路径随快照传递；第三方插件、脚本依赖、特殊授权与自定义资源配置尚未全面验证。后台不是完整复制的用户应用数据环境。
- 预览未完整复刻 AE 素材导入的 ICC/OCIO 转换。高精度交付请烘焙并检查色彩管理。
- AE 正在预览播放时保留当前版本，停止播放后再应用新缓存。正式 Render Queue 输出前等待 Cached 100% 并关闭 Live sync，或先烘焙。
- 缓存、快照、后台私有配置及状态文件位于主目录 `Cavalry AE Native/default`。AE 工程不嵌入这些文件。跨机器需收集相应素材，确认所有工程不再引用后才能清理缓存。
- 编辑端只读取场景并导出快照；预览队列和烘焙参数操作全部在独立后台执行，不在用户编辑工程创建或删除临时节点。

产品名与原生文件名为 `BridgeNa2_Cavalry`。内部 AE matchName `Cavalry Native Preview`、参数顺序、缓存协议/目录及安装的 `Cavalry AE Native.js` 文件名保留，以兼容旧工程和启动标签。Mac 使用本地签名，未 Apple 公证；Windows 文件未商业签名；安装器只处理本包隔离标记，不修改系统安全设置。

测试范围见 `验证记录.md`。源码包不含 Adobe SDK 和编译工具链，二进制安装无需开发环境。
