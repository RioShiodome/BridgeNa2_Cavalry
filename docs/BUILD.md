# Build 4.6.4

C++17. macOS Command Line Tools (clang++, lipo, Rez, codesign), Adobe AE SDK Examples directory in AE_SDK, and LLVM-MinGW in MINGW_BIN. Run `python3 tools/build.py` for a Mac Universal bundle, Windows x64 .aex and qttestability.dll. The Windows target is Windows 10/11 x64. The release is experimental until verified in real AE/Cavalry on Windows.

`python3 tools/bundle.py` combines the source resolver, renderer, scheduler, channel, preview and bake modules into one installed JS; it also embeds the AE composition and bake UIs with shared JSON and cache-root helpers. The foreground render guard is no longer used. Qt and Cavalry are not redistributed. The tiny Windows DLL dynamically resolves public Qt Core exports from the installed Cavalry runtime.

Mac: the bundle resource launch-mac.js uses Launch Services and an isolated CFFIXED_USER_HOME, with hidden/non-activating launch and exact ownership of the returned process. Windows: the native idle callback invokes the installed renderer/launch-windows.ps1 with system Windows PowerShell; it uses a private desktop, a job object, child-only environment variables and Qt's QT_LOAD_TESTABILITY entry point. Qt normally loads qttestability.dll and calls qt_testability_init; that enables QStandardPaths test mode before the Cavalry UI is constructed. No process injection or vendor modification. Both preference and app-data paths are checked by the role JS. QT_FATAL_CRITICALS prevents continuing after failure to load the startup DLL; the child's HOME channel is isolated as a second guard.

`python3 tests/run-tests.py` runs JS regressions and C++ ASAN/UBSAN cache tests plus resampling checks. After building, run `pwsh -NoProfile -File tests/windows-scripts.test.ps1` for PowerShell syntax, embedded C# compilation, Win64 structure sizes and diagnostic PE/checksum checks. Run `pwsh -NoProfile -File tests/windows-installer.test.ps1` for real-file staging, backup, rollback and workspace fixtures, including Unicode paths. These scripts also accept `powershell.exe` on Windows. The recorded runs use PowerShell 7 on Mac and do not exercise Win32 APIs, Windows PowerShell 5.1, UAC or NTFS file-lock behavior. See the verification report for remaining host tests and performance methodology.

`python3 tools/package.py` creates Mac, Windows and source 4.6.4 ZIPs on the Desktop; it checks Mac signatures, hashes, ZIP integrity and the one-JS requirement. The Windows package includes `plugin/renderer/launch-windows.ps1` and `qttestability.dll`; these must be installed together beside the .aex. Scripts use UTF-8 BOM + CRLF for Windows PowerShell 5.1/ExtendScript, with CRLF-only CMD wrappers. The read-only `Check-Compatibility-Windows.cmd` checks the environment, installed files and package checksums on the target PC. Runtime uses built-in PowerShell; Node/Python are build/test dependencies only.

Build SDK used: Adobe Effect API 13.27 headers from public AfterEffectsSDK mirror; obtain the Adobe SDK under applicable Adobe terms. SDK/toolchains are excluded from the source package. stb_image and compiler-runtime notices are included. See THIRD_PARTY.md.

Run `tests/ae-script-parse.jsx` from AE after bundling. It reads project sources, uses isolated Windows-path mocks, compiles the complete create-layer script without executing it, and writes `build/ae-script-parse.json`. No user layers or installed bridge globals are modified. When invoking via macOS AppleScript, use DoScript with `$.evalFile(File(path))` so `$.fileName` points to the test file. This host-engine check is necessary: Node accepted the 4.6.3 path regex that AE ExtendScript rejected. It does not test Windows host rendering.
