4.5 编辑交互实测再次通过：250 帧动画缓存期间 16 次播放头操作和 2 次图层修改成功，拖动期间继续发布缓存；50 ms 采样的最大间隔为 54 ms，最终播放头保持 35。记录：build/interaction45/cache/proof-result.json。已备份并更新本机插件及单个 Cavalry JS 到 4.5.0，哈希和代码签名验证一致；未改正在使用的工作区、保存或关闭用户工程，需正常重启两端载入。

## 4.4.1 启动修复验证

现场安装版本仍为 4.3。后台子进程已退出，但其监督进程持续写 ready，任务结果属于旧 ID；这是本次无限启动的直接原因。修复使用系统存活检测、内核自动释放锁、按请求 ID 的回应超时及加载前确认，增加显式后台检查/登录入口。

本次新启动的独立 Cavalry 成功完成 8 帧测试快照；随后终止该测试子进程，监督进程正确写 error、child=0 并退出，未保留 ready。遗留 renderer.lock 目录不再阻塞启动，退出后内核锁可重新取得。新增 JS 回归覆盖 ready 但无回应、旧任务结果、加载超时、长时间烘焙及检查模式跳过旧烘焙。实际宿主验证不等于所有工程或授权状态均可正常运行。

检查窗口实测通过：跳过旧 bake 请求，新请求在同一个后台进程完成 8 帧渲染并退出检查模式。Mac 4.4.1 已安装，文件哈希与构建一致，codesign 验证通过。

随后使用**实际已安装的 JS 与 launch-mac.js**运行独立编辑场景：250 帧缓存期间进行 16 次播放头操作（20–35 帧）、2 次图层位置修改（y=7、14），全部生效；拖动期间继续发布缓存，编辑后重新完成 250 帧。50 ms 采样的最大间隔 57 ms，最终播放头保持 35。证据为 build/interaction441/cache/proof-result.json。这不包括 AE 实际 RAM 播放帧率的完整测量。

## 4.4 性能改动与历史测试

保留 4.3 独立进程方案，不在编辑端调用 render/setFrame。后台第一批 2 帧，后续按耗时选择 1–64 帧，目标约 200 ms。编辑端去掉播放头变化造成的发布延迟，合并指纹检查，文件控制轮询最多每 100 ms。连接保持时发送待命心跳，避免 90 秒后再编辑又重新启动后台。

AE 每 100 ms 检查元数据，渐进更新最多约每 400 ms 应用；首次可用版本和完整版本优先。使用 AEGP Item View Suite 查询预览播放状态，播放时不修改实时层参数，停止后接收新版本。旧 matchName、参数顺序和缓存协议保持兼容。

Windows 由系统 PowerShell 创建自有后台进程、独立桌面和带 kill-on-close 的 Job。通过 Qt 自带 QT_LOAD_TESTABILITY 入口载入随包 qttestability.dll，调用公开 QStandardPaths 测试配置 API；JS 同时验证 preferences 和 appData 目录，防止误用编辑端。没有代码注入、系统目录重定向或修改 Cavalry 文件。启动失败不回退前台渲染。

## 通过的自动检查

- worker：编辑端禁止渲染和改播放头；连续拖动仍发布新段，内容编辑取消旧任务，重新生成快照，旧完整缓存保留，空闲不重复重建。
- renderer：自适应批次上限、慢帧降批、取消、单尾帧命名、异步场景身份、已发布前缀重启续传、已完成烘焙不重复执行。
- Windows 路径大小写/分隔符以及 preferences/appData 双重隔离验证。
- 背景派发、场景路径/脏标记保持、请求身份、烘焙参数与取消、JSON fallback、场景指纹。
- C++ 缓存 ASAN/UBSAN、透明通道、并发读取、像素转换对照。
- Windows .aex / qttestability.dll x64 交叉编译；插件入口、DLL 导出与依赖检查。
- PowerShell 语法、嵌入 C# 编译、安装器中文/空格路径和重复安装不重复添加启动标签（在 macOS PowerShell 中使用工作区 fixture）。这不是 Windows 进程启动实测。

## 4.4 历史失败及剩余边界

4.4 候选版的完整编辑交互复测没有通过。初次复测的 16 次设帧、2 次图层位置操作均生效，但后台任务随后停住，测试最终超时，不能计为通过。后续独立实例多次在加载/导出阶段停止，采样堆栈明确显示 SignInDialog::startLicenceValidation → promptForAuthentication；控制台显示 Verifying licence。没有尝试绕过授权。新增后台加载重试/超时提示，旧缓存保留。

4.3 已由用户确认消除了闪动；其 6 次拖动/2 次编辑测试属于历史证据。4.4.1 新增的独立编辑交互回归现已通过（见上文），但不宣称所有交互场景均验证。AE 播放时固定版本的逻辑已编译，真实 RAM 预览播放场景未作完整自动验证。

Windows 没有 AE/Cavalry 实机，因此发布测试版，重点仍需确认实际 Qt 启动入口、独立桌面图形后端、授权、字体/素材、中文路径及 Windows 10/11 宿主行为。不存在“编译通过即等于兼容完成”的承诺。

开发中曾尝试原生进程初始化启动器，被本机 Bitdefender 标记并移除；该方案已废弃，不包含在发布包。最终使用系统 PowerShell 和 Qt 正常启动入口，未关闭安全软件、添加排除或恢复被拦截文件。最终包仅包含 .aex、启动 PS1、Qt 入口 DLL 和一个 Cavalry JS。

第三方插件、登录/上传、全部编码格式、Intel Mac、AE 2024/2025、复杂场景和所有色彩管理组合未全面实测。快照导出仍在编辑进程，复杂场景可能短暂耗时。
